### 解决的问题：
现在这些病理 Foundation Model 到底**是在学习“真正的病理生物学信息”，还是偷偷学习了“医院、染色、扫描仪、制片流程”等技术信息**？

1.第一层：Representation-Level Robustness
FM 提取出来的 embedding 空间，到底主要按照“病理生物学”组织，还是按照“医院技术特征”组织？
2.第二层：Output-Level Robustness
判断医院中的设备、染色等错误混淆信息是否真的会**影响下游预测**（cluster、生存预测、分类等等）

### 模型的输入输出
input
level1：patches
每个patch有两个标签
1.biological class
EX. tumor/normal，tumor subtype
2.medical center
level2：FM embedding
pathoROB（**评估病理基础模型鲁棒性的基准框架**）分析的embedding
也就是不同FM眼中该WSI张什么样子

output
1.robustness index
根据embedding的临域，判断是biology决定还是medical center决定
2.average performance drop，APD
当医院和disease label出现伪相关时（换一个医院，其label不同），下游模型的性能会掉多少
3.clustering
无监督clustering得到的cluster，是根据病理组织cluster还是根据hospital

构造dataset
尽量将biology与medical center构造的互相垂直
### 文章思路来源
biology和technical sign**同时存在**，但FM中**没有机制告诉其后者不要学**
且technical feature**更容易学会**（整家医院的风格差不多，且有测试得到的数据支撑）
一个例子，训练级中
hospital A中得出90% tumor
hospital B中得出90% normal
模型可能会**认为A更容易tumor，B更容易normal**
这样的模型是**严重shortcut**的

所以本文是在挑战一个评价习惯
**==high下游accuracy不等于robust representation==**

### 总结
病理 Foundation Model 虽然在很多 benchmark 上表现很好，但它们的 representation 可能同时编码真正的病理形态和医院、染色、scanner 等非生物学信息；当医院来源与疾病标签发生伪相关时，下游模型可能利用这些技术信息走捷径，并在新的数据分布下产生严重错误。作者因此构建了 PathoROB，用真实多中心且尽量平衡的数据，把 biology 和 medical-center confounding 拆开，系统比较 20 个 pathology foundation models 在 representation、下游预测、clustering、retrieval 等层面的 robustness，并进一步研究无需重新预训练 FM 的 robustification 方法。
